# Лабораторная работа — Модуль 05: Product Client

**CSE5032 · Разработка веб-сервисов · Модуль 05**

Нужно было сделать клиентское приложение для управления товарами через отдельный Web API. Я разделил сервер и MVC-клиент. Именованный `HttpClient` настраивается в приложении и получается через `IHttpClientFactory`; сервис выполняет HTTP-операции. На странице можно читать, создавать, изменять и удалять товар. Сейчас покажу полный сценарий и обработку ответа сервера. При ошибке клиент показывает сообщение вместо аварийного завершения.

---

## Цель

Создать клиентское приложение ASP.NET Core, которое получает и изменяет товары через Web API и корректно показывает ошибки.

## Краткий отчёт

Решение состоит из `ProductApi` и `ProductClient`. MVC-сервис `ProductApiService` реализует `IProductApiService`, получает настроенный именованный клиент `ProductApi` через `IHttpClientFactory` и выполняет HTTP-запросы. Ошибочные ответы преобразуются в понятные сообщения интерфейса.

| Часть задания | Реализация | Для чего |

| 2. HttpClient | `AddHttpClient("ProductApi")`, `BaseAddress` из конфигурации, `IHttpClientFactory` | Переиспользовать настройки клиента и не создавать отдельный `HttpClient` для каждого запроса |
| 3. Сервис | `IProductApiService` и `ProductApiService`: GET all/by Id, POST, PUT, DELETE | Собрать HTTP-взаимодействие в отдельном слое |
| 4. Список | GET загружает товары в таблицу | Показать данные Web API в MVC |
| 5. Чтение по Id | Форма поиска получает товар либо сообщает 404 | Показать детали выбранной записи |
| 6. Создание | Форма отправляет POST, затем возвращает пользователя к списку | Добавить запись через API |

| 8. Удаление | DELETE отправляется после страницы подтверждения | Защитить от случайного удаления |

## Модель `Product`

| Поле | Тип | Назначение |
|---|---|---|
| `Id` | `int` | Идентификатор |
| `Name` | `string` | Название |
| `Description` | `string` | Описание |
| `Price` | `decimal` | Цена |
| `Quantity` | `int` | Количество |

## HTTP-методы

| Действие | HTTP-метод | Endpoint | Успешный ответ |
|---|---|---|---|
| Список | `GET` | `/api/products` | `200 OK` |
| Детали | `GET` | `/api/products/{id}` | `200 OK` |
| Создание | `POST` | `/api/products` | `201 Created` |
| Изменение | `PUT` | `/api/products/{id}` | `200 OK` |
| Удаление | `DELETE` | `/api/products/{id}` | `200 OK` |

## Как используется `IHttpClientFactory`

В `ProductClient/Program.cs` регистрируется именованный клиент `ProductApi` с адресом из настроек. `ProductApiService` получает `IHttpClientFactory` через DI и создаёт настроенный клиент вызовом `CreateClient("ProductApi")`. Новый `HttpClient` вручную на каждый запрос не создаётся.

## Вывод

Реализованы операции GET списка и записи, POST, PUT, DELETE и обработка требуемых HTTP-ответов. Конфигурация `IHttpClientFactory` отделяет создание HTTP-клиента от бизнес-операций сервиса.
